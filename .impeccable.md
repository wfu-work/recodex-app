## Design Context

### Users
The primary user is the project owner using a phone to safely control a personal Mac or Linux workstation running Codex. The job is operational and focused: pair a device, choose an allowlisted workspace, send a prompt, monitor streaming output, interrupt when needed, and inspect Git state before deciding whether to commit or push.

### Brand Personality
Quiet, capable, and trustworthy. The app should feel like a precise remote console rather than a chatbot demo or landing page.

### Aesthetic Direction
Use a restrained mobile-first control-room interface: dense but readable information, clear state indicators, calm neutrals, purposeful status color, compact navigation, and strong affordances for risky actions. Avoid decorative hero sections, playful mascots, heavy gradients, glass effects, and generic chat-app styling.

### Design Principles
- Put operational state first: connection, workspace, running session, and confirmation requirements should be instantly visible.
- Keep the default path fast: connecting, selecting a workspace, sending a prompt, and checking Git should require minimal movement.
- Treat risk with friction: commit and push actions need clear confirmation and visible output.
- Design for phone ergonomics: compact controls, stable text areas, bottom navigation, and no hidden critical actions.
- Prefer quiet polish over spectacle: alignment, spacing, and state feedback matter more than decoration.
